claude code技巧学习第二篇，本篇文章将会介绍更多的 claude code使用技巧，继续深入讲解插件、Subagent、自动化等概念，助力大家更好地使用 claude code

1. Plugin(插件)

前面我们已经介绍了 ：

  • skills: 为了完成任务，而将一套的提示词、流程、模板、脚本等打包到一起的能力包，在 claude code需要的时候可以自己调用。
  • Hooks: 在 claude code中运行到了关键节点的时候插入的规则，比如动手前拦截、结束前验收。

除了这些之外，还有一个重要的组件 MCP Server，它的作用就是将外部的工具和数据源链接到 Claude code，比如浏览器、邮箱、数据库、notion 等。它的作用就是调用外部工具以获取数据。

而现在我们介绍的 Plugin(插件)就是集中了这些东西，赋予了 claude code处理一整套工作的能力。比方说我们进行一个视频渲染的工作流时，可以使用 skills来管理视频的分镜，在特殊节点，特定的 hooks会来检查此时工作区的状态是不是符合要求，最后 claude code还可以调用外部工具来渲染整个视频。插件本质上让前面碎片化的流程更加聚合、更加自动化。

接下来我们要怎么来使用和管理插件呢？

2. Subagent（子智能体）

首先相信大家已经对这个东西会多或少的已经有一些了解了，我们先来了解一些基础的概念。

首先什么是智能体呢？

  • 除了帮你回答之外，还能直接帮你完成任务的AI，都被成为智能体。

子智能体有什么优势呢？ 为什么需要子智能体？

子智能体的优势在于并行和上下文独立，比如在主智能体派发任务給多个子智能体去执行时，多个智能体可以同时去执行不同的任务，这样任务执行的效率远远大于一个智能体执行单独任务所有流程的总耗时。

同时每一个智能体拥有自己独立的上下文，这样就不会因为信息过多过杂，而导致结果出现太多的偏差。每一个智能体完成任务的调研、执行之后，将自己的汇总结果传给主智能体。这样让整个任务执行系统的流程更加简洁。

那么现在我们怎么才能自己来创建一个子智能体呢？我们可以通过 claude code的对话框来直接创建一个智能体，但是如果我们需要对整个智能体进行更加精细的把控，那么就需要在 claude code的终端命令工具中，使用 /agent命令来进行创建。这也是为什么我们要在最开始的时候先介绍 claude code CLI工具的原因，有一些功能在 VS Code插件中还没有适配好，未来或许会适配这些功能。

4. CLAUDE.md文件

相信大家都能看到我们在这个项目的根目录有一个 .claude文件夹，相信大家都已经猜到了它的功能，它其实就是用来管理整个项目的 claude配置信息的文件夹。

那么 CLAUDE.md是用来干什么的呢？ 其实它就是一个专门向 claude code说明这个项目信息的文件，用来说明这个项目的技术栈是什么，在执行任务之前需要注意什么，什么应该做，什么绝对不能做，以及我们个人的一些偏好，都可以在这个文件中向 claude code描述。有了这个文件的信息， claude code在接手我们项目的时候就不需要再询问我们一些前置信息了。

在 claude code中 输入 /init命令， claude code就会为我们自动生成 CLAUDE.md文件了。

此时就可以看到，文件树中多了一个 CLAUDE.md文件

当然要注意，CLAUDE.md在开启这个项目的会话的时候会进入这个会话的上下文，虽然不会像 hooks那么强制，但是既然要加载进上下文，我们也不希望它太长，所以在编写的时候，我们尽量不要长篇大论，这里大家也可以去参考一下其他的开发者是怎么编写的。
